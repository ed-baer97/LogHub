# Caspian LogHub

Цифровая биржа **внутрирегиональных** грузоперевозок Мангистауской области: заявки отправителей, борт перевозчика, попутные грузы вместо порожнего возврата.

Кейс — только перевозки внутри области (магазины, фермы, стройки, отдалённые посёлки). Не порт и не международный транзит.

Доступ строится на трёх вещах сразу: **роль**, **владение** (своя заявка / свой борт / своя точка) и **статус**. Чужой объект API отдаёт **404**, а не список «вам запрещено».

## Как устроен интерфейс

- **Главная (`/`)** — страница о проекте. Кабинетов и живой карты здесь нет.
- **Войти** — email + пароль. После входа открывается кабинет роли. Чужой кабинет по прямой ссылке недоступен. Логотип ведёт в свой кабинет. Выход — на главную.

| Роль | Кабинет | Кого создаёт |
|------|---------|--------------|
| Супер-админ | Дашборд системы (карта, счётчики, списки). Операции не запускает | Только **админов**. Себя в списке не видит |
| Админ | Обзор (без живого парка) и пользователи. Заявки, борт и пункты не правит | **Отправителей и перевозчиков**. Можно заблокировать и сбросить пароль. Себя, админов и водителей в списке нет |
| Отправитель | Новая заявка, мои заявки, **пункты**. Пока заявка открыта — правка и отмена. На карте только борт своего рейса | Свои точки на карте (справочник области не редактирует) |
| Перевозчик | Биржа (`open`) → взять на компанию. «Мои рейсы» → назначить **свободный борт**. «Парк» | Борт = водитель + машина. Можно отключить борт |
| Водитель | Только свой борт и назначенный рейс. **Начать маршрут** / **Завершить** | — |

**Борт** в интерфейсе — одна сущность (в БД по-прежнему таблица `vehicles`). Маршрут OSRM, движение и пробег включаются только на этапе `transit` (кнопка «Выехать»). GPS с телефона необязателен.

## Статусы заявки

```
open → taken → assigned → arrived → loading → transit → delivered
open / taken / assigned → cancelled
```

В API `IN_TRANSIT` хранится как `transit`.

| Шаг | Кто |
|-----|-----|
| Разместить / править / **удалить** `open` | Отправитель |
| Отменить `open`, `taken`, `assigned` | Отправитель (борт при этом освобождается) |
| Взять с биржи (`open` → `taken`) | Перевозчик |
| Назначить свой idle-борт (`taken` → `assigned`) | Перевозчик |
| «Я прибыл» (`assigned` → `arrived`) | Водитель |
| «Начать погрузку» (`arrived` → `loading`) | Водитель. Дальше отмена отправителем запрещена |
| «Выехать» (`loading` → `transit`) | Водитель. Строится маршрут |
| «Завершить рейс» (`transit` → `delivered`) | Водитель. Борт снова свободен |

Пропускать этапы нельзя (`assigned` → `transit` запрещено).

Справочник населённых пунктов (Актау, Шетпе, …) — платформенный каталог (`sender_id` пустой). Свои точки отправителя видны только ему (плюс рейс, если точка уже в заявке).

## Вход

В сиде одна учётка:

| Роль | Email | Пароль |
|------|--------|--------|
| Супер-админ | `superadmin@caspian.kz` | `demo` |

Остальных заводите в интерфейсе. Пароль задаётся при создании (по умолчанию тоже `demo`) и показывается **один раз** в тосте. В списках пользователей пароль больше не отдаётся.

Пункты Мангистау в сиде есть. Заявок, парка и прочих учёток при старте нет. Заблокированная учётка не входит.

Цепочка для проверки с нуля:

1. `superadmin@caspian.kz` / `demo` — создать админа.
2. Войти как админ — создать отправителя и перевозчика.
3. Отправитель — при необходимости добавить пункт, разместить заявку.
4. Перевозчик — создать борт, взять заявку с биржи, назначить борт.
5. Водитель — прибыл → погрузка → выехать → завершить рейс.

## Что умеет MVP

1. **Биржа.** Заявка между пунктами, лента только `open` для перевозчика.
2. **Карта и навигатор.** MapLibre + OSM. Polyline и движение — после старта водителя (OSRM, кэш в БД).
3. **Попутки.** Коридор маршрута: крюк и экономия порожняка.
4. **Цена.** Рекомендация по км, весу и типу груза.
5. **Пробег на дашборде супер-админа.** «С грузом» и «Пустые». У админа — урезанный обзор без live-деталей флота.
6. **Роли и ownership.** Кто кого создаёт — таблица выше. Админ не ведёт парк, заявки и пункты.

## Стек

- Backend: FastAPI, SQLAlchemy 2, PostgreSQL (Docker) или SQLite локально, SSE
- Frontend: React 18, Vite, MapLibre GL
- Маршруты: публичный OSRM, кэш в БД
- Очередей Celery / Redis нет: один процесс uvicorn, движение — задача на конкретный рейс

## Локальный запуск

Если Docker Desktop выключен, бэкенд пишет в **SQLite** (`backend/caspian.db`).

```bash
cd backend
python -m venv .venv
# Windows: .venv\Scripts\activate
# Linux:   source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

В другом терминале:

```bash
cd frontend
npm install
npm run dev
```

Открыть **http://localhost:5173** — Vite проксирует `/api` на бэкенд. API: http://127.0.0.1:8000/docs

Первый старт: таблицы, пункты Мангистау, супер-админ. После перезапуска uvicorn сессии сбрасываются — войдите снова.

Матрица доступа:

```bash
cd backend
python -m pytest
```

PostgreSQL вместо SQLite:

```bash
docker compose up -d postgres
# Windows PowerShell:
$env:DATABASE_URL="postgresql+psycopg://caspian:caspian@localhost:5432/caspian"
```

## Продакшен на Linux (Docker + публичная ссылка)

```bash
docker compose up --build -d
```

Фронт: порт **80**, API: **8000**. Скрипт: `scripts/deploy-linux.sh`.

```bash
cloudflared tunnel --url http://localhost:80
```

Запасной вариант: `ngrok http 80`.

## Экономика (питч)

- Без биржи порожний пробег ~**40%**.
- Обратная загрузка в коридоре маршрута (детур ≤ 90 км).
- Дизель **32 л / 100 км**, **295 ₸/л**.
- Выигрывают перевозчик (топливо), отправитель (срок и цена), акимат (видимость потоков).

## Что за рамками хакатона

Платежи, ЭЦП / SMS, нативное приложение, скоринг перевозчиков, тахографы, Celery/Redis, несколько инстансов API.
