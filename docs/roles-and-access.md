# Роли и доступ

Доступ строится на трёх вещах сразу: **роль**, **владение** (своя заявка / свой борт / своя точка) и **статус**. Чужой объект API отдаёт **404**, а не «вам запрещено» — чтобы не светить чужие id. Исключение: неверная роль на эндпоинте даёт **403** («Недостаточно прав»).

Реализация: `backend/app/access.py`, `backend/app/roles.py`.

## Роли

| Роль | Кабинет | Кого создаёт | Что видит |
|------|---------|--------------|-----------|
| Супер-админ | `/dispatcher` — дашборд системы (карта, счётчики, списки). Операции рейса не запускает | Только **админов**. Себя в списке не видит | Все заявки, борт, пункты, полная аналитика |
| Админ | `/dispatcher` — обзор без live-деталей флота и пользователи | **Отправителей и перевозчиков**. Блокировка и сброс пароля. Себя, админов и водителей в списке нет | Заявки и пункты; аналитика урезана (нет базы порожняка и live GPS) |
| Отправитель | `/sender` | Свои точки на карте (каталог области не редактирует) | Свои заявки; борт только своего рейса |
| Перевозчик | `/carrier` | Борт = водитель + машина. Можно отключить борт | Биржа (`open`) + свои рейсы; только свой парк |
| Водитель | `/driver` | — | Свой борт и назначенный рейс |

Роль `dispatcher` в коде — алиас админа (legacy).

Админ **не** ведёт парк, заявки и пункты: нет create/update заявок, бортов, точек.

## Кто кого создаёт

```
супер-админ  →  админ
админ        →  отправитель, перевозчик
перевозчик   →  водитель (вместе с бортом)
```

Супер-админ не создаёт отправителей. Админ не создаёт админов и водителей.

## Видимость объектов

### Заявки

| Роль | Список |
|------|--------|
| staff | все |
| отправитель | `sender_id = я` |
| перевозчик | `status = open` **или** `carrier_id = я` |
| водитель | `vehicle_id` = мой борт |

После `take` чужой перевозчик заявку уже не видит (404).

### Борт

| Роль | Условие |
|------|---------|
| staff | все |
| перевозчик | `owner_id = я` |
| водитель | `driver_id = я` |
| отправитель | борт привязан к **моей** заявке (`current_order_id` или `orders.vehicle_id`) |

Пока заявку не назначили на борт, отправитель парк не видит.

### Пункты

| Роль | Условие |
|------|---------|
| staff | все |
| отправитель | каталог (`sender_id IS NULL`) + свои точки |
| перевозчик | каталог + origin/dest открытых или своих заявок |
| водитель | каталог; если есть рейс — ещё origin/dest этого рейса |

База борта (`home_id`) — только пункт каталога, не личная точка отправителя.

## Правила мутаций

- Редактировать и **удалять** заявку можно только в статусе `open` и только отправитель-владелец.
- Отмена — статусы `open`, `taken`, `assigned`. С `arrived` отмена запрещена (409). При отмене борт освобождается (`idle`).
- Взять с биржи (`take`) — только перевозчик, только `open`.
- Назначить борт — владелец заявки-перевозчик, статусы `taken` или `assigned`. Борт idle, активен, с водителем, грузоподъёмность ≥ веса.
- Этапы рейса (`arrive` → `start-loading` → `start-route` → `complete-route`) — только водитель этого борта, без пропусков.

## HTTP-коды (типичные)

| Код | Когда |
|-----|--------|
| 401 | нет/протух токен, «Сессия истекла» |
| 403 | роль не та, учётка заблокирована |
| 404 | нет объекта **или** чужой объект |
| 409 | конфликт статуса, занятый email/госномер, борт в рейсе |

## Сессия и блокировка

`is_active = false` — вход 403, действующие JWT отзываются (`token_version`). SSE тоже не пускает. Пароль при создании/сбросе приходит один раз в `initial_password` и в списках не повторяется. Минимум 6 символов; пустое поле при создании — сервер генерирует.
